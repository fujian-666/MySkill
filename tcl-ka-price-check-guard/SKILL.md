# TCL KA 价差核对 · 质量固化层（Guard）

> 这是**规则与门禁层**，不负责插列/刷值（那属于执行层）。
> 它把多轮返工换来的教训做成**可执行断言**：任何一版交付前，跑不过门禁就不许出。
> 一句话定调：**这就是简单的匹配价格的事，有就有，没有就没有，事实胜于雄辩。**

## 0. 何时用 / 不用

| 场景 | 用不用 |
|---|---|
| 已有一张核对过的 xlsx，要出下一版 / 复检 / 改名 | ✅ 必用 |
| 制表备注与核对情况表对不上、业务填完原因要回填 | ✅ 必用 |
| 换月份 / 换渠道 / 换战区，要确认不串月不套列位 | ✅ 必用 |
| 从零插五步列、原始表清洗、抓销售明细 | ❌ 属于执行层，见 `references/WORKFLOW.md` |
| 只是回答某个型号多少钱 | ❌ 直接查源表 |

## 1. 六条铁律（动手前默念）

1. **四元组**：战区 × 渠道 × 月份 × 版本，任一不同 = 另一张表。**不套列位、口径、源表、基线**；价格表绝不串月。配置全在 `config/profile.json`，换表先换配置。
2. **事实数据说话**：匹配不到 ≠ 没有。必须走完四路链才下结论；「有就写有（哪张表哪行多少钱），没有就写没有」，不硬凑、不拿口径差把简单问题复杂化。
3. **铁律冲突先暂停确认**：任何两条规则打架，先问，不擅自破坏规则、不盲从、不猜。
4. **只改该改的格**：数值列、差额公式、金额链、真公式文本一律不碰；改文案就只改文案。全簿 diff 必须等于 plan 格集合。
5. **每条被纠正的规则，当场变成可执行断言/脚本**，不能只写进记忆。这是本 skill 存在的唯一理由。
6. **改完必独立复核**：一致性 ≠ 真一致；「标一致的行」也要查差额是不是真的 0。

## 2. 每版固定动作（一步不许省）

```
① identify_table.py "<件>"                 表型识别 + 月份交叉校验，冲突即停
② openpyxl 只读建 plan                     断言目标格、旧值、新值；不与 COM 同时持有
③ COM 逐格写 + 逐格读回                    Calculation=-4135 必须在 Open 之后
④ --next 取当天下一版名，另存新文件         绝不覆盖上一版
⑤ 独立 verify 全簿 diff                    值层/公式层双扫，真公式文本零改动
⑥ delivery_gate.py --prev <上版> --expect-diff N --plan <plan.json>   21 项全过
⑦ 记忆 / 日志固化
⑧ present_files 交付
```

🔴 门禁没全过 → **禁止交付**。别用「先发再补」「为过校验放宽判据」绕过。

## 3. 三个价格 = 三列 = 三个专属词（最易错）

| 列 | 核对对象 | 差额列 | 唯一允许的「不对」描述 | 白名单 |
|---|---|---|---|---|
| K (11) | 供价核对：渠道供价 H vs 大区供价 I | J | **供价不对** | 一致 / 退货 / OA备案价 |
| U (21) | 公司授权底价核对：R vs 大区零售价 S | T | **授权底价不对** | 同上 |
| AE (31) | 总部价格核对：AD 总部最低零售限价 | — | **总部价格不对** | OA 证据行保留原文 |

- 三个价格定义不同，**严禁串词、严禁一个简称抹平**。曾把 U 列也写「供价不对」，被当场推翻。
- 业务视图只留待办标注：价格表出处、行号、取数细节、OA 窗口说明**不进 K/U/AE**；结论说明从情况表内清空，**只在对话里单独发给负责人**。
- 情况表类型名、F 列对账价、OA 证据行（含 OA 号/审批人/日期）按现行口径保留，没点名不动。

## 4. 四路匹配链 + 型号归一化

```
外部大区表「连锁+区域连锁价格表」  F型号 / G连锁供价 / K当月零售价（双层表头，r3 起）
  → 外部总部表「线下渠道」          D型号 / G最低零售价（r5 起；取 G 不取 F）
  → 「淘汰机价格表」兜底            C型号 / D现净供价（带 (特一/二/三) 为等级机）
  → 内嵌「战区X月价格表」+ 三张 OA 截图（D型号 / H最低零售价 / I结算价）
  → 仍无 → 才写「请业务提供OA依据」
```

- **AD 只用外部总部 G + 淘汰机兜底**，内嵌表不参与 AD。内嵌「总部价格表」「制表(2)」「OA备案」等属历史遗留，不作真值源。
- 统一键 = `re.sub(r"[^A-Z0-9]", "", s.upper())`；精确失败必须跑 `candidates()` 分级去 `-A/-JN/-PRO/-SE/-C` 再下结论。
- 等级机判**原始串**（归一化会吃掉中文括号）；**只有等级机价不得硬凑标准价填 AD**。
- 表头 r1 批注是口径真值源（含税含券 / 有OA按渠道供价−分摊 / 一票机=渠道供价），判差异前先读。
- OA 按「销售日期 + AB 的 OA 号」分段，禁整月一刀切；AB 填死（OA报备价/统一供价/包销机）= 非差异不列。

## 5. 零基准保护（别为过校验放宽判据）

- `I=0 且 S=0`（大区价没匹配到）时 `=IF(S=0,0,R-S)` 让 J=H、T=0；标「不对」但差额 0 **不是假差异**。
- 校验第 7 项按 `I!=0 / S!=0` 豁免，第 8 项保证这些行**不标「一致」**，逻辑闭环。
- 曾想「所有 T=0 都豁免」来让校验变绿 —— 已否决。先坐实 I=0/S=0 才豁免。

## 6. 制表 ↔ 核对情况表：双向一致 + 事后回填

- **双向**：制表标了「没找到价格/价格有差异」的正向行 == 情况表去重行；反之情况表列了的，制表侧必须有不一致标注；说明价必须等于制表 H / R / AD。退货红冲只列正向，不列情况表。
- **回填**：业务在情况表 G（原因）、H（OA号或价格依据）填完后 → 供价核对→K、公司授权底价核对→U、总部底价核对→AE，追加 `｜业务反馈：{原因}；依据：{依据}`，**不覆盖原标注、幂等、另存新版本**。
- G/H 全空时**不要硬改文件、不要替业务编原因**，只把规则和工具备好。

## 7. 命名与版本

```
原名—<负责人>M-D核对VN.xlsx      （连接符 em dash U+2014，无括号）
```
- M-D = 当天；**VN = 当天第 N 版，从 V1 起算**。
- 🔴 **跨日一律重新从 V1 开始，绝不沿用前一天版本链**；当天内误编号按当天顺序重编号，旧版不追溯改名。
- 交付件存业务往来目录对应月份下，**不放桌面**。
- `delivery_gate.py --next "<任一现有件>"` 自动给出当天下一版名。

## 8. 脚本速查（全部在 `scripts/`）

| 命令 | 作用 |
|---|---|
| `python scripts/model_key.py` | 型号归一化自测（PASS 才可参与匹配） |
| `python scripts/identify_table.py "<件>"` | 表型识别 + 月份交叉校验 |
| `python scripts/check_tz_cs_consistency.py "<件>"` | 10 项双向一致性，退出码 0 = 全过 |
| `python scripts/delivery_gate.py "<件>" --prev "<上版>" --expect-diff N --plan "<plan.json>"` | 21 项交付门禁 |
| `python scripts/delivery_gate.py --next "<件>"` | 当天下一版名 |
| `python scripts/backfill_reason_to_tz.py --file "<源>" --out "<新>" --apply` | 业务原因回填（默认预览） |
| `from style_check_sheet import apply_standard` | 核对情况表标准样式（COM 内调用，幂等） |

配置：`cp config/profile.example.json config/profile.json`，按四元组填列位、基线、三列词数、源表路径。
也可用环境变量 `KA_PROFILE` 或各脚本 `--profile` 指向别的配置文件。

## 10. 环境

- Python 3.10+，`openpyxl`；COM 写入需 `pywin32` + 本机 Excel（仅 `backfill` / `style` 用）。
- 只读脚本（识别、一致性、门禁、--next）**不依赖 Excel**，可在任意机器跑。
- Windows 下命令用绝对路径解释器；Git Bash 的 PATH 会丢，别依赖 `python` 在 PATH 里。
