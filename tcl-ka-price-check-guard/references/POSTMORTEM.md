# 多版返工根因复盘

> 一个「简单的匹配价格」的活，前后返工十几版。这份表是那些返工换来的东西。
> 原则：**每条被纠正的规则，当场变成可执行断言/脚本**，不能只写进记忆。

## 根因 → 返工 → 挡法

| 根因 | 造成的返工 | 现在的挡法 |
|---|---|---|
| 匹配键只 `upper` 去空格，漏 `-A` / `-JN` / 连字符 | 连续多版假「无此型号」；后来又两次漏配 AD | `model_key.py` 统一键 + 分级去后缀 + 等级机判定 + selftest |
| 只查外部价格表就下「没有」结论 | 一批行内嵌战区表其实有价 | 四路匹配链写死；每版全量逐行回归 |
| 不同口径的数硬相减 | 含税含券固定 1000 元口径差 → 凭空造出 444 条差异 | 表头 r1 批注必读；口径不串；该系列定稿「无差异」 |
| 只看单列不看品类 | 智能门锁写成无效待办 | 查「原始数据」商品名判品类 |
| 只改正文不改结论 | 结论区留旧话术、行数自相矛盾 | 结论区现行直接清空；每版做数字自洽扫描 |
| 校验只查「两边一致」，没查「标一致是否真一致」 | 被追问「数据没有问题了吧」后补 6~8 项 | 一致性 10 项：差额 =0 / ≠0、零基准豁免 |
| 三个价格用一个简称抹平 | 把 U 列写成「供价不对」 | 第 10 项「三列不串词」+ 门禁 G5 |
| 沿用前一天版本链 | 跨日文件名仍续前一天的 V13/V14 | 门禁 G1 + `--next` 自动取当天下一版名 |
| 内部取数出处进业务视图 | 数十格含表号/行号/OA 窗口说明 | 业务视图只留待办标注；结论单独发负责人 |
| 为过校验放宽判据 | 曾想「所有 T=0 都豁免」 | 先坐实 I=0/S=0 才豁免，第 8 项闭环 |
| 手动计算模式下缓存不更新 | 差额列值不随改动重算 | 逐格重写原 `.Formula`；禁 `CalculateFullRebuild()` |
| `End(-4162)` 求末行 | AutoFilter 状态漏 83 行 | `UsedRange.Row + Rows.Count - 1` + openpyxl 交叉校验 |
| COM 批量赋值 | `Range.Value = 二维数组` 静默只写首行 | 逐格写 + 逐格读回 |
| openpyxl 与 COM 同时持有 | 图片写回崩溃 | 只读建 plan → 关闭 → 再开 COM |
| 改脚本直接覆盖正式件 | 中途错误污染交付件 | 沙箱重跑 + 逐格比对一致，才允许覆盖 |
| 拿单项比恒等式 | 比 Q 不比 Q+P，报 231 条假异常 | 先验 `X+Y=Q+P`，再造异常 |

## 被用户纠正的话 → 变成的规则

| 原话（意） | 固化结果 |
|---|---|
| 「供价就是匹配供价，到手价就是零售价」 | 口径定义写进 RULES §5，禁止跨口径相减 |
| 「Z11 系列供价和到手价与制表匹配是没有差异的」 | 该系列定稿无差异，历史误判撤销 |
| 「匹配不到可能是 OA 或战区价格表的，事实数据说话」 | 四路匹配链 + 全量回归 |
| 「有就有 没有就没有，事实胜于雄辩」 | 不硬凑、不拿口径差复杂化；有写哪张表哪行，没有写没有 |
| 「制表里的不一致要和核对情况表一致，业务填完原因要回填」 | 双向一致性 10 项 + `backfill_reason_to_tz.py` |
| 「上一版不需要改了吗？数据没有问题了吧」 | 补 6~8 项，查「标一致的行是否真一致」 |
| 「核对结果后期发给我就行，不用让业务知道」 | 结论区从表内清空，单独发负责人 |
| 「这样不要写，就说供价不对就行了」 | K/U 长文案一律简化 |
| 「各是各的描述，不要搞混了，三个价格是不一样的定义」 | 三列专属词 + 第 10 项门禁 |
| 「今天都 12 号了，不应该从 V1 开始吗？」 | 跨日重新从 V1 起算 + 门禁 G1 |
| 「一定要记忆、固化、复盘、修坑、强化」 | 本 skill + 21 项交付门禁 + 反向验证 |

## 方法论沉淀

1. **事实先于服从**：用户指出的每一条，先独立查数据坐实，再改；不盲从、不硬凑。
2. **不为了表忠心硬改文件**：G/H 全空时不编原因、不生成空转文件；规则备好，等数据到再跑。
3. **校验要能自证**：正向全过不够，必须拿已知有缺陷的上一版做**反向验证**，证明门禁真能拦。
4. **结论区与正文同步**：只改正文不改结论，等于埋一颗自相矛盾的雷。
5. **日志 append-only，记忆压缩重整**：逐版细节进日志；长期记忆只留现行规则，放最前面防截断。
6. **脚本内序号 ≠ 交付版号**：内部 `rerun_10_v14.py` 之类是开发序号，交付 `V2` 是当天第 2 版，两套编号别混。
7. **零基准豁免要闭环**：豁免条件（I=0/S=0）必须由另一项校验保证这些行不标「一致」，否则就是放水。

## 每版固定动作（最终形态）

```
identify_table → plan（只读断言）→ COM 逐格写+读回 → --next 取名另存
→ 独立 verify 全簿 diff → delivery_gate 21 项全过
→ 记忆/日志 → 交付
```

数据、公式、金额链一律不碰。
